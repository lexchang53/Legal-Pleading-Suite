# twlegalrag-search

本技能提供台灣法律法源的雙軌檢索、效力查驗與引用防護體系：
1. **司法裁判與勞動裁決軌道**：透過 `twlegalrag` CLI 檢索並產生可引用的法源封包（bundle），並以 `scripts/check.py` 執行確定性引用檢查。
2. **主管機關行政函釋與規則軌道**：透過 `tw-legal-rag` MCP 工具（`search_legal_references` / `get_legal_reference`）進行語義探索與二階段效力狀態查驗。

當任務需要建立在真實、可追溯、可驗證的台灣司法裁判與主管機關法源資料上，而不是憑空摘要或未驗證的法律敘述時，應使用本技能。

## 雙軌架構與工具分流矩陣

AI 接收到法律問題後，必須先辨識法源性質，分流至對應工具：

| 法源類型 | 適用範圍 | 執行管道 | 核心工具 / 指令 | 引用標記與防護機制 |
|---|---|---|---|---|
| **法院裁判／憲法裁判** | 司法院各級法院裁判、釋字、憲判字 | **CLI 管線** | `twlegalrag search`<br>`twlegalrag pack` | 標記 `[J1]`、`[J2]`...；以 `allowed_citations` 白名單 ＋ `scripts/check.py` 驗收。 |
| **不當勞動行為裁決** | 勞動部不當勞動行為裁決（`doc_id` 以 `arb:` 開頭） | **CLI 管線**（自動並列） | `twlegalrag search`<br>`twlegalrag pack` | 標記 `[J1]`、`[J2]`...；**嚴禁稱「判決」**；以 `scripts/check.py` 驗收。 |
| **部會行政函釋／行政規則** | 78 個中央機關之解釋令函、行政規則、裁量基準 | **MCP 管線** | `search_legal_references`<br>`get_legal_reference` | 標記 `[R1]`、`[R2]`... 或全稱字號；**二階段效力查驗**（核對 `status` ＋ 全文逐字吻合）。 |

## 開始前環境檢查與降級提示

### 1. 檢查 CLI 工具
確認執行環境中可使用 `twlegalrag` 指令。若未安裝或無法執行，提示使用者安裝：
```bash
pip install twlegalrag
```

### 2. 檢查 MCP 工具與主動降級提示
當使用者要求查詢**行政函釋、主管機關令函或行政規則**時，AI 應先檢查當前環境是否具備 `tw-legal-rag` MCP 工具（`search_legal_references` 與 `get_legal_reference`）。

> 🔴 **MCP 缺失時之強制提示規則**：
> 若環境未掛載 `tw-legal-rag` MCP 工具，AI **必須主動輸出以下標準提示**，嚴禁自行改用未經驗證之爬蟲、HTTP 請求或憑記憶捏造函釋：
> > 「目前環境未連接 tw-legal-rag MCP 服務（缺少 search_legal_references 工具）。目前僅能提供司法裁判與勞動裁決檢索；部會行政函釋請掛載 MCP 後查詢。」

## 指令與工具調用規範

### 1. CLI 指令規範（裁判與勞動裁決）
請直接使用 Python 執行 `twlegalrag` CLI，不使用 PowerShell 包裝腳本。常用指令如下：
```bash
twlegalrag health
twlegalrag search "<查詢詞>" -n <數量> --read
twlegalrag pack "<查詢詞>" -o <輸出路徑.json> -n <數量>
```
* 如果檢索結果之後要被引用、驗證或交由下游生成法律文本，優先使用 `pack`（預設顯式帶入 `-n 6`）。
* **引用檢查統一使用 `scripts/check.py`**，不要直接呼叫 `twlegalrag check`：
```bash
python scripts/check.py <bundle.json> <answer.txt>
```
腳本會驗證檔案，調用 twlegalrag 進行比對，並解析檢查報表內容以回傳對應的退出碼（0為通過，1為不通過，2為待人工複核），供流程判斷是否通過。若回答或書狀中已有 `[J1]`、`[J2]` 等標記，在交付前必須以此腳本驗證。

### 2. MCP 工具規範（部會行政函釋）
* **語義探索**：調用 `call_mcp_tool(ServerName="tw-legal-rag", ToolName="search_legal_references", Arguments={...})`
  * `query`（必填）：自然語言主題查詢詞。
  * `authority`（選填）：指定主管機關精確名稱（如 `"勞動部"`、`"財政部"`、`"金管會"`、`"法務部"`）。
  * `source_kind`（選填）：`"administrative_interpretation"`（函釋）、`"administrative_order"`（行政命令）、`"tax_interpretation"`（稅務函釋）等。
  * `max_results`（選填）：1～10 筆（預設 5）。
* **字號精確調卷與效力查驗**：調用 `call_mcp_tool(ServerName="tw-legal-rag", ToolName="get_legal_reference", Arguments={"serial": "<發文字號>", "authority": "<機關名稱>"})`
  * 回傳全文與 `status`（`valid` / `repealed` / `ceased` / `replaced` / `unknown`）。

## 法源性質辨識與引用規則

twlegalrag 檢索範圍涵蓋多元法源，AI 在處理檢索結果與生成引用時，**必須先辨識法源性質，嚴格遵守對應之引用規範與禁令**：

| 法源類型 | 識別特徵 / 字號格式 | 性質與效力說明 | 引用規範與禁令 |
|---|---|---|---|
| **憲法裁判 / 大法官解釋** | `憲判字`、`釋字第 N 號` | 具拘束全國各機關及人民之最高憲法效力 | 最強權威法源。引用格式為「司法院釋字第 N 號」或「憲法法庭 OOO 年憲判字第 N 號」，標記 `[Jn]`。 |
| **法院裁判** | 各級法院裁判字號（如 `最高法院 112 年度台上字第 9 號`） | 司法審判實務見解，依審級具拘束力與前例參考價值 | 依下述 §法院審級優先順序 處理，標記 `[Jn]`。 |
| **行政函釋／命令** | 部會發文字號（如 `勞動條 3字第1150148315號函`、`台財稅...`） | 僅為主管機關內部之解釋性規定與裁量基準（行政程序法 §159），供執法參考，對法院無直接拘束力 | 🔴 **絕對禁止將行政函釋稱為「法院見解」、「判決」或與法院判決混為一談**。引用時必須明確標註發布機關名稱與完整發文字號，採 `[Rn]` 標記或全稱引述。 |
| **不當勞動行為裁決** | 裁決字號（如 `112年勞裁字第...號`），`doc_id` 開頭為 `arb:` | 勞動部裁決委員會之行政救濟裁決，**非司法裁判** | 🔴 **絕對禁止稱為「判決」或「法院見解」**。引用時必須明確標示為「勞動部不當勞動行為裁決委員會見解」或「勞動裁決」，標記 `[Jn]`。 |

## 法院審級優先順序規則

在檢索、整理與引用**法院裁判**時，依下列順序優先處理：

1. 最高法院裁判優先。
2. 其次為臺灣高等法院及其分院裁判。
3. 若前述法院裁判不足以支撐檢索目的，再補充其他法院裁判。

當多筆裁判都與爭點相關時，應優先整理與引用較高審級法院的裁判，並在摘要與輸出中依法院層級排序，而不僅依原始檢索順位排列。

如果 bundle 同時包含不同法院層級的裁判，應先檢視最高法院裁判是否已足以支撐主要論證；只有在不足時，才補充高等法院及其分院裁判作為輔助。

## 查詢筆數規則

除非使用者另有指定，預設查詢筆數如下：
- `twlegalrag search` 預設使用 `-n 5`，用於快速確認檢索方向與結果相關性。
- `twlegalrag pack` 預設使用 `-n 6`（此為技能顯式帶入參數，工具 CLI 預設為 5），優先取得較精簡、較容易整理的核心裁判集合。
- `search_legal_references`（MCP）預設使用 `max_results: 5`。
- 若法律爭點較廣、結果分散、或最高法院裁判不足，才逐步提高到 `-n 8` 或 `-n 10`。

## 查詢詞建構原則

### 1. 司法裁判查詢詞建構
* **一般語義檢索**：以「**法律構成要件關鍵字 + 法律效果關鍵字**」為基礎組合查詢詞（例：`競業禁止 違約金 過高`、`租賃契約 終止 拒絕返還`、`董事 忠實義務 損害賠償`）。
* **案號精確調卷與口語簡寫正規化**：
  - 若使用者提供標準案號（例：`最高法院 112年度台上字第9號`）或純短案號（例：`112台上9`、`108台上大2470`），可直接作為查詢詞。
  - 🔴 **口語雙重簡寫正規化**：若使用者同時輸入「法院簡稱＋非標準短案號」（例：`北院 112訴100`、`最高院 112台上100`、`高院 112上100`），TLR 後端正則會失效並錯誤降級為關鍵字搜尋。**AI 必須在送入 CLI 前主動正規化為標準案號**（例：`臺灣臺北地方法院 112年度訴字第100號` 或直接使用純短案號 `112訴100`）。
  - **大法庭案件**：最高法院大法庭正式字別為 `台上大`、`台抗大`（例：`108台上大2470`），最高行政法院為 `上大`、`抗大`，嚴禁自創非官方字別。
* **查詢詞擴展規則**：只允許書寫變體（條款 ↔ 約款、返還 ↔ 回復），嚴禁跨越法律效果邊界：
  - 🔴 **終止 ≠ 解除**（繼續性契約將來生效 vs 一次性契約回復原狀）
  - 🔴 **解除 ≠ 撤銷**（契約效力消滅 vs 意思表示瑕疵）
  - 🔴 **無效 ≠ 撤銷**（自始不生效力 vs 行使撤銷權）
  - 🔴 **合意解除 ≠ 法定解除**
* **多爭點處理**：若案件同時涉及多個法律概念，以各自獨立的查詢詞分別檢索後再合併。
* **正反雙向查證原則（避免確認偏誤）**：
  1. 正面檢索：尋找支持該主張的案例（例：`撤銷定暫時狀態處分 情事變更`）。
  2. 反面檢索（絕對必要）：主動加入反向關鍵字（`駁回`、`敗訴`、`不予准許`）尋找實務陷阱與邊界。
  3. 綜合評估：同時並陳正反見解與敗訴風險。

### 2. 行政函釋查詢詞建構
* **主題語義探索**：提煉「部會權責事項 ＋ 具體爭議概念」（例：`扣繳義務人 未依限申報 處罰`、`罹癌 留職停薪 復職`），並善用 `authority` 參數鎖定主管機關。
* **完整函釋字號調卷**：若使用者提供完整發文字號（例：`台財稅第881945861號`、`勞動條3字第1150148315號`），**跳過語義檢索**，直接調用 `get_legal_reference(serial=...)` 進行精確調卷與效力查核。

## 標準作業流程（SOP）

### 流程 A：司法裁判與勞動裁決標準流程（CLI 管線）

1. 先以 `twlegalrag health` 確認檢索服務可用。
2. 理解使用者的法律爭點或欲查詢之裁判字號，整理成適合檢索的查詢詞。
3. 執行 `twlegalrag search "<查詢詞>" -n 5 --read` 快速預覽。
> 🔴 **CHECKPOINT 1 — 方向與候選確認**：展示 search 結果摘要（裁判字號、法院層級、案由、爭點命中情形）。
> * **跨法院同字號消歧義**：若檢索詞為通用字號（如 `112上易100`）回傳多個不同分院，必須列出各分院名稱供確認。
> * **民刑多文書核對**：若同案號同時存在民事（`TPSV`）與刑事（`TPSM`）裁判，必須嚴格核對 `case_category` 與案由，避免誤引同號刑事判決。
> 確認檢索方向與目標文書正確後再繼續。
4. 依法院審級優先順序審閱，使用 `twlegalrag pack "<查詢詞>" -o bundle.json -n 6` 產生法源封包。
5. 讀取封包，擷取 `citation_id`（`[J1]`、`[J2]`...）、`case_history`、`fulltext_excerpt`。
   * **實體見解與引文必須嚴格以 `fulltext_excerpt` 理由全文為準，嚴禁以 `hit_excerpt` 作為論述依據**。
   * 排除 `case_history` 顯示已被上級審廢棄之裁判。
6. 要求生成內容以 `[J1]`、`[J2]` 標註引用，並依 `verification_instructions` 執行見解層自查（OPINION-LAYER SELF-CHECK）。
7. 將生成內容寫入暫存檔，執行 `python scripts/check.py <bundle.json> <answer.txt>`。
> 🔴 **CHECKPOINT 2 — 引用驗證確認**：展示 check 檢查結果（0 通過 / 1 失敗 / 2 需人工複核），確認無誤後始得交付。

---

### 流程 B：主管機關行政函釋標準流程（MCP 管線）

1. 確認環境具備 `tw-legal-rag` MCP 工具；若缺失，輸出標準降級提示並終止函釋流程。
2. **第一階段：語義探索或字號調卷**
   * 若為主題查詢：調用 `search_legal_references`（可指定 `authority` 與 `source_kind`），獲取候選清單與摘錄。
   * 若為具體字號：直接進入第二階段。
3. **第二階段：強制執行效力狀態查驗（Status Verification）**
   * 對欲引用的每一筆函釋字號，**強制調用 `get_legal_reference(serial=...)`** 取得全文與 `status` 欄位。
   * **效力狀態機處置規則**：
     * 🟢 `status == "valid"`：確認現行有效，可作為主管機關實務見解引用。
     * 🔴 `status == "repealed"` / `"ceased"` / `"replaced"`：**絕對禁止**作為現行法令依據引用（僅能在探討歷史沿革時加註廢止說明）。
     * 🟡 `status == "unknown"`：資料庫尚未完成效力校驗，可引用但**必須於文中明示**「本函釋效力尚未經資料庫自動驗證，適用時請向主管機關法規系統複核」。
4. **逐字引文與標記規範**：
   * 引述內容必須 100% 存在於 `get_legal_reference` 全文正文中。
   * 引用標記採 `[R1]`、`[R2]`... 或直接標註完整發文字號（例：「勞動部 115 年 6 月 12 日勞動條 3 字第 1150148315 號函」），**嚴禁使用 `[Jn]` 標記，嚴禁送入 `scripts/check.py` 檢查**。

---

### 流程 C：裁判與函釋複合檢索流程
若任務同時需要法院裁判與主管機關函釋：
1. 分別依流程 A 取得裁判 `bundle.json`，依流程 B 取得驗證有效的函釋全文。
2. 輸出時採**嚴格分區呈現**：
   * 「一、 司法審判實務見解」區塊：標註 `[J1]`、`[J2]`，以 `scripts/check.py` 驗收。
   * 「二、 主管機關行政函釋與行政規則」區塊：標註 `[R1]`、`[R2]`，註明發布機關、發文字號與效力狀態。

## scripts

### `scripts/check.py`

此腳本用於包裝 `twlegalrag check`，統一執行**裁判封包**引用檢查流程。

用途：
- 檢查 bundle 檔案與回答檔案是否存在。
- 呼叫 `twlegalrag check` 的 Python API 或進行 CLI 輸出解析。
- 回傳對應狀態的退出碼，供流程判斷是否通過：
  - **0**：通過 (pass)
  - **1**：不通過 (fail，例如偵測到引用了不在 bundle 內的字號，高度疑似捏造)
  - **2**：待人工複核 (needs_review，例如引文存在性檢查不符，但字號皆在 bundle 內)

建議用法：
```bash
python scripts/check.py <bundle.json> <answer.txt>
```

## 輸出要求

使用本技能輸出結果時，應包含以下資訊：
- 本次檢索之法律爭點摘要與使用之查詢詞。
- **司法裁判清單**：`citation_id`（`[Jn]`）、裁判字號、審級歷程（是否維持/廢棄）、關鍵理由摘要、`check.py` 驗證結果。
- **行政函釋清單**：發布機關、完整發文字號、發布日期、`status` 效力查驗結果（有效／未驗證／已廢止）、核心解釋意旨。

## 失敗處理

| 觸發條件 | 一線修復 | 仍失敗兜底 |
|---|---|---|
| 完整裁判案號精確調卷查無結果 | 1. 檢查字號拼寫與合法格式（如更審 `更一`、大法庭 `台上大`）。<br>2. 留意查無結果之客觀原因：可能為法定不公開案件（兒少、性侵、少年事件）或新宣判案件之入庫時間差（ETL lag）。 | 告知使用者「查無此案號不代表裁判不存在，但因資料庫未收錄，不得臆測該案內容」，建議至司法院官方「法學資料檢索系統」確認，並停止引用 |
| 環境未掛載 `tw-legal-rag` MCP 工具且使用者要求查函釋 | 輸出標準提示，提醒掛載 MCP 端點 `https://tlr.dr-legal.com.tw/mcp` | 明確告知目前僅能提供司法裁判與勞動裁決，部會行政函釋暫無法檢索，不使用爬蟲繞過 |
| `search_legal_references` 回傳空結果 | 調整查詢詞，移除 `authority` 或 `source_kind` 篩選條件以擴大範圍 | 告知使用者「語料庫非窮盡收錄，查無不代表函釋不存在」，建議至主管機關法規系統確認 |
| `get_legal_reference` 查無指定字號 | 核對字號格式（全半形、臺/台、「字第」/「第」等變體）重新查詢 | 告知使用者查無此字號，嚴禁據此宣稱該字號為捏造，停止引用該函釋 |
| `get_legal_reference` 顯示 `status` 為 `repealed` / `ceased` | 尋找主管機關是否有發布取代之新令函 | 嚴禁作為現行依據引用；若為沿革說明，必須明確標記「已廢止／停止適用」 |
| `scripts/check.py` 顯示裁判引用不一致 | 依回報訊息修正對應的 `[Jn]` 標記，核對 excerpt 原文修正見解 | 重新執行 `pack` 更新 bundle，再重新生成並檢查 |
| 裁判在 `case_history` 顯示已被上級審廢棄 | 尋找有無發回更審後之最新裁判，或改用其他未廢棄之最高法院裁判 | 僅能在說明訴訟歷程時引用，不得當作現行有效前例 |

## 規則（絕對禁止）

- 🔴 **絕對禁止捏造**裁判字號、發文字號、裁判理由、函釋內容或引文。
- 🔴 **絕對禁止性質混淆**：嚴禁將行政函釋或勞動裁決稱為「法院判決」或「法院見解」。
- 🔴 **絕對禁止引用已廢棄裁判或已廢止函釋**作為現行有效前例。
- 🔴 **絕對禁止將 `hit_excerpt` 直接作為逐字引述依據**（必須以 `fulltext_excerpt` 或 `get_legal_reference` 全文為準）。
- 🔴 **絕對禁止未經 `get_legal_reference` 核驗效力即直接引用行政函釋**。
- 🔴 **絕對禁止繞過依賴**：在 CLI 或 MCP 不可用時，嚴禁自行改用未經驗證之網頁爬蟲替代。

## 範例

### 範例 1：法院裁判檢索（CLI 管線）
* **使用者需求**：找出台灣法院對於競業禁止違約金過高的實務見解。
* **執行路徑**：`twlegalrag health` → `twlegalrag search "競業禁止 違約金 過高" -n 5 --read`（CHECKPOINT 1 確認方向）→ `twlegalrag pack ... -o bundle.json -n 6` → 擷取最高法院裁判 `[J1]`、`[J2]` → 生成草稿 → `python scripts/check.py bundle.json answer.txt`（CHECKPOINT 2 確認通過）→ 交付。

### 範例 2：主管機關行政函釋檢索與效力查驗（MCP 管線）
* **使用者需求**：查詢勞動部關於罹癌勞工留職停薪期滿復職保障的函釋。
* **執行路徑**：
  1. 呼叫 MCP `search_legal_references(query="罹癌 留職停薪 復職", authority="勞動部")`。
  2. 取得候選 `勞動部 115 年 4 月 13 日勞動條 3 字第 1150147957 號函`。
  3. **強制呼叫** `get_legal_reference(serial="勞動條3字第1150147957號", authority="勞動部")` 取得全文與 `status`。
  4. 確認 `status` 為 `valid` 或 `unknown`，提取全文中關於「解僱最後手段原則」之正文。
  5. 輸出時標註發布機關、發文字號與效力狀態，明確說明此為行政主管機關解釋，非法院判決。

### 範例 3：環境缺失 MCP 時之降級處置
* **使用者需求**：請幫我查財政部最新關於扣繳義務人處罰的函釋。
* **執行路徑**：偵測環境無 `tw-legal-rag` MCP 工具 → 主動輸出提示：「目前環境未連接 `tw-legal-rag` MCP 服務（缺少 `search_legal_references` 工具）。目前僅能提供司法裁判與勞動裁決檢索；部會行政函釋請掛載 MCP 後查詢。」→ 結束流程，不使用爬蟲繞過。
